# 市场观察视频模板

一套面向中文财经、加密货币和美股解释视频的制作工作流。它不是“给一段文案自动套PPT”的模板：先核实事实，再由真实男声音频确定时间轴，随后把每条 `[[cue:...]]` 字幕路由到合适的数据和连续动画，最后通过可重复seek、抽帧、完整解码的验收才允许交付MP4。

适合做：公司财报、宏观数据、ETF资金流、加密机制、新手教程、监管政策、风险事件和中长期投资解释。模板强调信息密度和证据边界，不把单日行情或一条媒体报道写成确定性的交易结论。

## 包含什么

| 位置 | 用途 |
|---|---|
| `财经视频引擎.md` | 标准财经视频引擎工作流，适合一般长视频与Shorts。 |
| `财经视频引擎V2.md` | 强化版工作流：固定背景图库、连续Hero、Hyperframes、六章节、动态路由和成片验收。 |
| `财经视频组件库/` | 可复用的财经组件、GSAP/D3/Motion Canvas路由器、检查器、测试和一键包装器。 |
| `财经视频组件库/motion-grammars/README.md` | 每种动画语法的适用条件、禁用条件和数据边界。 |

## 核心原则

1. 事实先于叙事。人物、数据、公司、政策和市场结论先核对一手来源；脚本显式区分事实、推测、观点、反证和失效条件。
2. 时长由信息密度决定。一个cue至少增加事实、机制、对比、风险、情景或行动；禁止为了凑5分钟重复结论。
3. 真实音频驱动字幕。先生成 `zh-CN-YunyangNeural` 男声，再用 `timeline.json` 的绝对时间对齐字幕、场景和媒体。
4. 长视频不是逐页PPT。选择1—2个可识别Hero对象，至少跨3个章节持续改变关系、数据焦点、状态或行动出口。
5. 数据动画不造数。D3镜头必须绑定 `product-facts.md` 的来源、日期、单位和口径；无法核实就阻断或标“机制示意”。

## 快速开始

```bash
git clone https://github.com/machao950/finance-video-engine.git
cd finance-video-engine

# 把财经视频引擎V2中的工作规则提供给制作Agent，写好项目的 script.md 和 product-facts.md 后执行：
bash ./财经视频组件库/启用智能动画.sh /绝对路径/你的项目/script.md
```

命令会安装锁定版本的依赖并输出：

```text
motion-plan.json          # 每个cue的机器可读动画路由
motion-plan.md            # 供创作审核的表格版计划
animation-preflight.md    # 阻断项、人工复核项与通过状态
```

若没有计划、检查失败、数据来源缺失、Hero不连续，或全片只有淡入/滑入，后续HTML演示与MP4合成应停止。

## 智能动画路由

| 字幕语义 | 动画语法 | 实际用途 |
|---|---|---|
| 资金流、ETF申赎、融资、分配 | `fund-flow` | D3确定比例与布局，GSAP推进流向。 |
| 营收、成本、利润、现金流 | `cashflow-waterfall` | 用瀑布桥解释增减项，而不是只报数字。 |
| 同比、环比、价格、估值、每日数据 | `line-bar-reveal` | D3折线/柱状揭示焦点，绑定真实时间区间。 |
| 因果、诈骗、攻击、清算、风险传导 | `risk-path` | GSAP SVG路径与节点状态变化。 |
| 多空、BTC/ETH、股票/凭证对比 | `comparison-split` | 通过同一Hero分裂、合并、对峙做同维比较。 |
| 事件发展、政策阶段 | `timeline-focus` | D3时间轴与GSAP焦点移动。 |
| 教程、核验、清单 | `tutorial-state-machine` | 每一步显示对象状态及成功/失败出口。 |
| 多层复杂机制、关键高潮 | `motion-canvas-shot` | 仅在普通DOM/SVG难以讲清时使用，不滥用。 |

路由器读取标题、章节与完整cue语义；随后仍要人工复核。自动匹配是制作建议，不是财经事实来源，也不替代镜头设计判断。

## 最小脚本格式

```markdown
title: 示例：ETF资金流为什么没有立刻推高价格？

## opening
[[cue:hook]]先说结论：资金流是边际买卖压力的线索，不是价格按钮。

## facts
[[cue:flow]]过去5个交易日净流入……

## mechanism
[[cue:path]]申购、做市、现货对冲与价格承接之间存在传导链。
```

同目录必须提供 `product-facts.md`，写明每项关键数据的来源、日期、单位和口径。路由器会阻断找不到匹配事实条目的数据cue。

## 六章节长视频结构

1. `01-opening`：问题、结论和前30秒证据兑现。
2. `02-facts`：口径、原始数据与限制。
3. `03-mechanism`：从事实到价格、公司或用户决策的传导链。
4. `04-countercase`：最强反证、替代解释和数据缺口。
5. `05-scenarios-action`：基准、乐观、风险情景以及可执行观察指标。
6. `06-closing`：回应标题，重申边界和唯一互动问题。

Shorts不机械裁剪长视频。它只保留“原创钩子、最小完整答案、1—2个机制或证据、具体边界”。

## V2成片验收

- 视频：默认1920×1080、25fps、H.264＋AAC。
- 动画：Hyperframes或等价实现必须支持暂停seek与重复渲染一致；不得依赖真实时钟或未设种子的随机数。
- 画面：字幕由真实音频时间轴驱动；旧场景先隐藏；Hero不复制双份；背景图库实际可见。
- QA：运行框架检查，逐章抽帧，重复seek关键状态，完整解码视频与音频，检查男声可懂度与字幕同步。

## 不包含的内容

本仓库不含个人视频项目、已渲染MP4、配音文件、背景图库、API密钥、登录会话、YouTube后台数据或用户财务数据。背景图与品牌素材应由每个项目按其授权、来源和频道规范另行提供。
